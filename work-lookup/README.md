# 업무 정보 도우미 네이티브 v6.7

## 실행

C++ / Windows API로 작성한 32비트 Windows 실행파일입니다. Windows 7 이상 x86/x64를 대상으로 제작했습니다. .NET, Java, Python, Excel, 별도 C++ 재배포 패키지, 브라우저 확장 설치가 필요하지 않습니다. Windows 기본 DLL을 사용하며 실행 중 인터넷에 접속하지 않습니다. 일반 사용자 권한으로 실행합니다.

기존 프로그램을 트레이 메뉴에서 종료하고 ZIP 전체를 새 폴더에 풀어 Run.cmd 또는 WorkLookup.exe를 실행하세요. 같은 세션에서 이전 네이티브 프로그램이 실행 중이면 새 실행은 기존 창을 표시합니다. 기존 설정과 DB 경로를 계속 사용합니다.

다른 앱에서 글자를 선택하고 설정한 단축키를 눌렀다가 손을 떼세요. 기본값은 F8입니다. 결과 카드의 글자를 선택해 Ctrl+C로 복사합니다. Esc 또는 다른 곳을 클릭해 포커스가 이동하면 카드가 닫힙니다. 기본 조회 범위는 모든 등록 정보입니다. ‘인터페이스만’ 범위는 정확히 인터페이스라는 분류에 한정됩니다.

## DB 관리 — 저장으로 확정

DB 관리 작업 버튼은 CSV 불러오기 / 저장 / 삭제 / 분류 삭제 / 분류명 변경입니다. 새 CSV, CSV 열기, 다시 읽기, 내보내기, 항목 추가·수정, 백업 복원 버튼은 제거했습니다. 목록 더블클릭으로 항목을 수정하는 기능도 제거했습니다. 검색어 입력 시 현재 분류 목록을 필터링합니다.

1. CSV 불러오기 버튼에서 파일을 선택합니다.
2. 분류명을 직접 입력합니다. 입력칸의 기본 제안은 파일명입니다.
3. CSV의 첫 행은 항상 칼럼 제목으로 처리합니다. 헤더 관련 체크박스는 없습니다.
4. 확인하면 현재 편집 DB에 추가되고 해당 분류 탭이 열립니다.
5. 저장을 누르면 파일과 조회에 최종 반영됩니다.

불러온 원본 CSV는 가져오기만으로 변경되지 않습니다. 기존 분류와 같은 이름은 허용하지 않으므로 다른 이름을 입력하세요. 한 분류 안의 조회키가 중복되거나 파일 형식이 잘못되면 현재 DB를 변경하지 않습니다.

삭제는 선택한 항목 하나를 지웁니다. 분류 삭제는 선택한 분류의 모든 항목과 탭을 지웁니다. 전체 탭은 삭제할 수 없습니다. 분류명 변경은 선택한 분류의 이름을 일괄 변경합니다. 기존 다른 분류와 같은 이름으로 변경할 수 없습니다. 마지막 항목이 사라진 분류 탭은 없어집니다.

불러오기, 이름 변경, 삭제는 메모리의 편집 목록에만 반영됩니다. 저장 전에는 조회가 마지막으로 저장한 DB를 사용합니다. 아직 저장한 DB가 없다면 저장 전 조회 결과는 비어 있습니다. 종료할 때 저장 여부를 묻습니다. 저장하지 않고 종료하면 편집 내용은 폐기됩니다.

저장 시 기존 DB는 backups에 자동 보관합니다. DB 파일이 아직 없으면 저장 위치를 선택합니다. 파일과 폴더에 읽기/쓰기/파일 교체 권한이 필요합니다. 임시 파일과 잠금 파일도 생성됩니다. 외부 편집을 감지하면 덮어쓰기를 중단합니다. 비협조적 외부 프로그램의 모든 경쟁까지 막지는 못합니다.

## 가져오는 CSV 형식

분류는 CSV 칼럼에 넣지 않습니다. 칼럼 위치만 사용합니다.

| 위치 | 값 |
| --- | --- |
| 1칼럼 | 조회키 — 필수 |
| 2칼럼 | 표시명 — 필수 |
| 3칼럼 | 상세정보 — 선택, 없으면 빈 값 |

칼럼 제목의 이름은 자유롭습니다. 첫 행은 항상 제목으로 제외하므로 CSV에는 제목 행을 넣으세요. 2~3칼럼만 허용합니다. 기존 프로그램이 저장한 분류 포함 4칼럼 DB는 프로그램 시작 시 기존 DB로 읽으며, CSV 불러오기용 2~3칼럼 파일과는 용도가 다릅니다.

```csv
IP,호스트명,설명
192.0.2.10,corebank-dev-01,개발 서버
192.0.2.20,api-test-01,테스트 서버
```

```csv
인터페이스ID,인터페이스명
ACCT_INQR_REQUEST,계좌 조회 요청
ACCT_INQR_RESPONS,계좌 조회 응답
```

UTF-8 CSV를 기본으로 읽고 UTF-8 BOM으로 저장합니다. CP949 파일은 CP949 허용을 체크한 뒤 불러옵니다. xlsx는 직접 읽지 않습니다. 최대 20MB, 50,000항목입니다. 내부 저장 DB는 분류/조회키/표시명/상세정보 4칼럼을 유지합니다. 조회키 대소문자를 구분합니다.

## 단축키와 조건

설정에서 F1~F11 단독 또는 Ctrl/Alt/Shift 조합을 선택합니다. 이미 사용 중인 단축키 등록이 실패하면 기존 단축키를 유지합니다. 설정은 %APPDATA%\WorkLookup\native-settings.csv에 저장합니다. 트레이 메뉴에서 DB 관리, 설정, 단축키 켜기/끄기, 종료를 선택합니다.

전역 마우스/키보드 후크와 드라이버를 사용하지 않습니다. RegisterHotKey로 단축키를 등록하고 눌렀을 때 SendInput으로 Ctrl+C를 요청합니다. 복사 가능한 텍스트만 대상으로 하며 이미지 글자 인식은 하지 않습니다. 관리자 권한 앱, 보안 문서, 은행 보안 정책에서는 자동 입력/클립보드 접근이 제한될 수 있습니다. 모든 앱·Windows 버전의 호환성을 보장하지 않습니다.

지원 가능한 기존 클립보드 내용을 보존 후 복원하며 다른 앱의 새 쓰기는 덮어쓰지 않습니다. 큰 데이터나 지원하지 않는 형식은 중단합니다. 잠깐의 점유는 재시도하며 기존 내용 확인/텍스트 읽기는 최대 1.2초, 복원은 최대 3초 기다립니다. 클립보드 기록/동기화에 일시적 복사 내용이 남을 수 있습니다.

## 점검 및 진단

Test-Windows.cmd는 합성 DB로 GUI/분류 탭/부분 복사/실제 자동 복사와 복원을 점검합니다. 제작 환경은 Linux이므로 실제 Windows 검사는 이곳에서 수행하지 않았습니다. Diagnose.cmd는 시작 단계와 Windows 오류 코드만 기록하며 선택 텍스트나 CSV 내용을 기록하지 않습니다.

개발용 Build.cmd는 32비트 MinGW-w64 개발 도구가 필요합니다. 이 도구는 사용 PC에는 필요하지 않습니다. 소스 및 개발용 테스트가 포함되어 있습니다. tests/check_binary.py는 내장 manifest의 앱 버전, 어셈블리 의존성 부재, 일반 권한, CLR 부재와 Windows DLL만 사용하는지 검사합니다. Python은 개발 검증에만 사용합니다.

## DB 목록에서 드래그·복사

셀을 클릭하면 읽기 전용 텍스트 영역이 열립니다. 같은 클릭에서 드래그해 원하는 부분을 선택하고 Ctrl+C로 복사할 수 있습니다. Ctrl+A는 해당 셀 전체를 선택합니다. 상세정보는 여러 줄로 펼쳐서 선택할 수 있습니다. Esc, 다른 곳 클릭, 목록 스크롤·검색·탭 전환으로 선택 영역이 닫힙니다. 글자는 편집되지 않고 DB와 저장 여부에 영향을 주지 않습니다. 셀 사이를 가로질러 여러 셀을 한 번에 복사하는 기능은 포함하지 않습니다.
